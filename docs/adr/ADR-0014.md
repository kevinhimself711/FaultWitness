# ADR-0014: Separate planned Iterations, corrective work, and Gate attempts

Status: accepted

Date: 2026-07-24

## Context

G02 把计划内实现、失败后的根因修复、以及完整 Gate Eval 重跑都编号为 `I-####`。这造成
两个错误：新增工作看起来像 Master Plan 原本就有；一个很小的 corrective 被迫承担新的
Iteration/Eval 规划、全局文档重定向、激活、候选、证据、关闭和 replacement Iteration。

I-0034 的实际修复提交涉及 4 个文件，但从规划到关闭共 5 个 commit、累计 49 次文件触碰。
当前 GetObject 根因在任何实现前已经产生一个 24 文件规划提交和一个 7 文件激活提交。
同时，历次失败均发生在 bootstrap、transport、deployment 或 access 前段，paid model call
为 0；冻结 Gate N 不是 corrective 成本的来源。

## Decision

采用三个不重叠的 work-item namespace：

- `I-####`：仅限 Gate 开始前由 Master Plan 冻结的计划内 Iteration。
- `C-G##-###`：Gate 内发现的单一根因 corrective。
- `A-G##-###`：只编排冻结 runner 的完整 Gate attempt。

已终态历史不回写。旧的 I-0021 至 I-0036 corrective 与 I-0020 至 I-0037 Gate attempts 通过
machine-readable legacy list 保留；新记录必须使用 C/A namespace。未实施的 I-0036/I-0037
终止并分别前向迁移为 C-G02-001/A-G02-001。

每个 C work item 只能拥有一个具名 root cause，只验证变化的 semantic branches；Gate L2
execution 和 full Gate Eval 必须为 0。Corrective 必须复用已有测试框架，禁止为普通根因新增
bespoke Eval harness。若变化触及外部 client、平台、凭据、镜像、解释器或传输 seam，关闭前
执行一次最小真实 seam proof，而不是等待完整 Gate attempt 首次触达。

从下一个新建的计划内 I 记录开始，Master Plan 必须逐项声明其外部 seam、真实语义 proof、
只读失败诊断和 artifact 路径；mock、memory backend 或 matrix-shape 测试不能单独证明 live
readiness。A work item 只能使用冻结的诊断 runner/command template，不得在 Gate attempt
现场试写命令或制造诊断工具。

> **适用性限定（2026-09-10）**：本条约束 Gate attempt 与 A/C work item。
> 按 `docs/runbooks/G03_BASELINE_READINESS.md:139` 的 Diagnostic scan mode 执行、
> 且产物标记 `diagnostic_only: true` 的只读观测，不是 Gate attempt，不在本条范围内。
> 此类观测可以新建诊断代码，包括在 `src/faultwitness_dev/` 下。
> 其产物永不可升级为 readiness evidence，亦不改变任何 Gate 状态。
> 依据：`docs/governance/GOVERNANCE_V2.md:88` 要求泄漏探针跑在第一轮之前。

全局 Claims、Master Plan、Validation final paths 与 Gate Report 的同步归属于 A attempt
规划/关闭，不计入 C engineering cost。A work item 的 `behavior_change` 必须为 false，且不得
声明 `src/`、`deploy/`、`tests/`、`config/` 或 `schemas/` 路径。

> **适用性限定（2026-09-10）**：本条约束 Gate attempt 与 A/C work item。
> 按 `docs/runbooks/G03_BASELINE_READINESS.md:139` 的 Diagnostic scan mode 执行、
> 且产物标记 `diagnostic_only: true` 的只读观测，不是 Gate attempt，不在本条范围内。
> 此类观测可以新建诊断代码，包括在 `src/faultwitness_dev/` 下。
> 其产物永不可升级为 readiness evidence，亦不改变任何 Gate 状态。
> 依据：`docs/governance/GOVERNANCE_V2.md:88` 要求泄漏探针跑在第一轮之前。

C record 将 corrective engineering、targeted verification、Gate execution 与 governance
synchronization 显式分账。A record 单独登记 Gate execution；耗时估算仅用于计划观察。

## Consequences

Corrective 工程、targeted verification、Gate attempt execution 和治理迁移/关闭分别核算。
一次 Gate failure 不再自动产生“corrective Iteration + replacement Iteration”双份生命周期。
命名直接暴露 Master Plan 外新增工作，后续可真实衡量计划质量。

本决定不降低或改变任何 validation N、质量/性能指标、权限、Ground Truth、locked test、
health oracle、模型 route、token/费用上限、phase 顺序或失败语义；耗时估算仍不是 kill timeout。
