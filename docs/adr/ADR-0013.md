# ADR-0013: Bind G02 Phase Caches to Candidate Subjects and Immutable Trial Evidence

Status: accepted

Date: 2026-07-23

## 2026-07-25 closure-freeze correction (normative)

The original decision used the phrase "all digests remain identical" for cross-candidate phase
inheritance and stated that I-0016 implemented that mechanism. Both statements are rejected as
over-broad:

- A candidate-wide SHA or aggregate evaluator digest is provenance metadata, not by itself proof
  that every phase changed. Treating either as universal invalidation recreates the full-matrix
  rerun that this ADR was intended to prevent.
- I-0016 implemented exact-key caching and reserved `inherited_from_manifest` in manifest v2, but
  did not implement a selective-inheritance writer, phase subject registry, or validator. G02 must
  not claim otherwise and must not add such a framework during closure freeze.

For the remainder of G02, an already-passing phase is inherited without execution only when all of
the following are recorded in the current Eval assets:

1. the source manifest, phase ID, artifact digest, original candidate, original producing revision,
   timestamps, execution count, and immutable private journal URI;
2. a path-level change-impact statement showing that no changed behavior, runner, fixture,
   threshold, permission, dataset, runtime image, configuration, environment, or external route is
   in that phase's semantic subject set;
3. the affected dependency boundary: a dependency is rerun only when its output semantics or
   runtime binding changed, not merely because its candidate label changed; and
4. `execution_count: 0` plus non-null `inherited_from_manifest` in the new manifest entry, while the
   original producing revision and artifact remain unchanged.

Candidate binding, static change-impact proof, failed phases, and phases downstream of missing or
changed outputs are never inherited. A destructive failure is never relabelled or retried on its
old candidate. If impact cannot be proven from existing frozen assets, the phase is affected and
must run. This correction changes no N, threshold, permission, model route, token/cost ceiling,
health-oracle window, or failure semantics.

## Context

ADR-0009 已分离 `candidate_sha` 与 `evidence_head_sha`，但没有冻结 phase、trial、cache、
inheritance 和 failure-resume 协议。G01 的单体串行 Eval、全矩阵重跑和 manifest SHA 级联
失效不得在 G02 重现。

## Decision

G02 Eval 是可寻址 phase DAG。每个 phase key 包含 candidate SHA、runtime/baseline image、
SUT image set、config、evaluator、dataset 和 environment fingerprint digest。Live/multi-trial
phase 在每个 trial 结束后原子写入 journal。

`--phase` 只运行一个依赖已满足的 phase；`--resume` 跳过 exact-key pass 并继续 pending 或
`infra_failed`；`--from-failed` 从最早未完成 phase 开始。`metric_fail` 不允许在同一候选
重跑。破坏性/soak phase 对同一 exact key 只运行一次。

Manifest v2 记录 phase status、start/end timestamp、cache key、artifact digest、private URI、
`candidate_sha`、runner-written `evaluated_revision`、`evidence_head_sha` 与 subject digests。
Evidence sync 禁止修改 `evaluated_revision`。Evidence-only descendant 在 artifact digests 完全
一致时继承结果；runner、fixture、threshold、workflow、dataset、config、deployment 或 runtime
变更会重新打开受影响 owner。未受影响 phase 只有在依赖闭包与所有 digest 完全一致时才能
建立 `inherited_from_manifest` 记录，原始 producing revision 保持不变。

Fail-fast 顺序固定为 manifest、candidate binding、static inheritance、upstream debt，然后才是
remote deployment、access、destructive scenario 和 paid model phases。

## Boundaries

本 ADR 只冻结协议。本 planning commit 不实现 cache、resume、manifest v2 或 runner；I-0016
拥有实现及负例。I-0020 只编排已冻结 runner，不得补写业务行为、fixture 或测试框架。

## Consequences

历史 evidence 不再因纯报告同步而重新部署，单次 transport failure 不再作废完整 live matrix，
且最终 Gate Eval 不能成为第二轮开发。
