# ADR-0019: Retract the Numeric Freeze of the Four-Turn Token Budget

Status: accepted

Date: 2026-09-11

## Context

`AMD-0007:168` states that the four-turn input budget "may not be raised". The budget it protects
is `MAX_CUMULATIVE_INPUT_TOKENS = 65_536`, declared at `src/faultwitness_dev/g03_readiness.py:117`
and mirrored at `config/g03/baselines-v3.yaml:5`, from which `FOUR_TURN_INPUT_LIMIT = 58_982`
(`:120`) and `REQUIRED_INPUT_HEADROOM = 6_554` (`:121`) are derived as 0.90 and 0.10 of it.

This came up while planning an observation-scope widening, where the budget appeared to forbid the
widening outright. It does not; but the reason it appeared to is worth recording, because the next
reader will hit the same wall.

## Named instrument defect

**The value has no derivation anywhere in the repository.** A search of all of `src/`, `config/`,
and `docs/` for `65536` / `65_536` returns exactly two hits: the constant itself and its config
mirror. No document states where it came from. It does not correspond to the context window of the
model actually used (`qwen3.7-plus-2026-05-26`), which is far larger. It was selected, and then
`AMD-0007:168` made it unraisable.

That is the pattern `docs/engineering/POSTMORTEM_MEASURE_BEFORE_FREEZE.md` was written about, and
which `ADR-0018` addressed for the `+0.10` margin: a numeric target frozen before any valid
measurement, after which governance converts an empirical guess into an unamendable rule.

**Most of the budget does not carry evidence.** Measured with the project's own
`four_turn_input_upper_bound_v3` (`:1779`), the fixed overhead of the four-turn bound — everything
that is not the packet — is 19902 tokens, and it decomposes exactly:

| Component | Tokens | Share |
| --- | --- | --- |
| Hypothetical assistant drafts (`MAX_COMPLETION_TOKENS × prior_count`, `:1801`) | **12288** | **61.7%** |
| System prompt, 4 turns | 4644 | 23.3% |
| Message framing (`MESSAGE_FRAMING_ALLOWANCE`) | 1280 | 6.4% |
| Request template (`REQUEST_TEMPLATE_ALLOWANCE`) | 1024 | 5.1% |
| Correction instruction text | 666 | 3.3% |
| **Total** | **19902** | 100% |

The 12288 is charged as 2048 × (0+1+2+3): every turn is billed the *maximum* completion length for
every prior turn, whether those turns occur or not. Against `FOUR_TURN_INPUT_LIMIT = 58982`, and
with the packet counted four times, the largest admissible packet is **9770 bytes**. The worst real
r9 packet is 9469 bytes, leaving **301 bytes**.

So the quantity that `AMD-0007:57` protects — "no service, sample, field, or measured value may be
removed to meet a token budget" — is being squeezed by an accounting convention, not by data
volume. Adding one upstream service to the trace query set costs 760 bytes (226 for
`trace_activity`, 534 for `trace_errors`, each multiplied by 7 windows × 4 turns) and is therefore
infeasible, while 61.7% of the overhead is reserved for drafts that may never be generated.

## Decision

The **numeric value** of the token budget returns to undetermined: "pending — set by the first run
that passes the validity checks".

The budget's **form is unchanged**. The four-turn upper bound is still computed for every packet;
it must still leave headroom; `token_preflight_v3` still returns `blocked` when exceeded;
`four_turn_token_headroom` still blocks live (`:3141-3142`); `budget_exhausted` remains a scored
failure that stays in the denominator and is not retried. Nothing is raised, waived, or exempted.

`AMD-0007:168`'s existing exception — "the only permitted correction is removing repeated
representation metadata without removing measurements" — **already authorizes** removing the
verbatim re-transmission of the packet on every turn. The packet is repeated representation; each
of its bytes is billed four times. Acting on that clause is compliance with it, not a breach.

## Not done here

No code changes. All five constants stand as written; `token_preflight_v3` is untouched; the
blocker still fires. This ADR changes documentation only, in the same shape as `ADR-0018`.

**This ADR does not edit `AMD-0007.md`.** That file is the seventh of ten hashed run inputs
(`_source_inputs_v3`, `g03_readiness.py:2852-2864`); editing it would change `config_digest` and
break resume identity, which is how r6 and r7 were lost. The retraction is recorded here and cites
`AMD-0007` by line number instead.

De-duplicating the four-turn representation is authorized but deliberately not done yet. The right
occasion is the move to agent-collected evidence, where each turn carries only the results it
requested and the repeated full packet disappears on its own. Doing it by hand first would solve a
problem that refactor deletes, and would change a second variable in a round whose purpose is to
change one.

## Also recorded

Two live inconsistencies, noted so they are not rediscovered as novel:

1. `AMD-0007:639-641` assigns remedies to "a future amendment", while `CLAUDE.md:91-92` directs
   that changes be recorded in `PLAN.md` with no amendment document written. Both cannot be
   satisfied. Standing practice — ADR plus `PLAN.md` — has already chosen the latter.
2. `AMD-0007:160-161` declares `max_tool_calls: 6` and concedes in the same sentence that it "is
   not implemented here". It sits in `config_digest` (`g03_readiness.py:169`,
   `config/g03/baselines-v3.yaml:21`) with no consumer — the live request body carries no `tools`
   key — yet still contributes to run identity. To be resolved with the tooling work, not here.

## Unfreezing conditions

The numeric budget is derived from the first run that passes the validity checks (leakage probe,
divergence, disclosure symmetry) and recorded in `PLAN.md`. Until then the form binds and the value
is pending.
