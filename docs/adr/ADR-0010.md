# ADR-0010: Use a Four-Family Flagd Scenario DSL for G02

Status: accepted

Date: 2026-07-23

## Context

G02 需要最小充分的故障实验室：四类 DSL、至少六类故障、32 个可执行 seed，并且必须
可确定性恢复。若直接引入通用 chaos 框架或第二个 SUT，会扩大权限面、平台兼容矩阵和
最终审计成本。

## Decision

固定 OpenTelemetry Demo 2.2.0 commit
`b74a7bc7bbe66099c61951f42b24dab8b6f02d18`，使用其 flagd UI read/write API。DSL 只有
`change_config`、`resource_capacity`、`dependency_network`、`runtime_data` 四个 family，
并只允许 `productCatalogFailure`、`adHighCpu`、`emailMemoryLeak`、`paymentFailure`、
`paymentUnreachable`、`kafkaQueueProblems` 六个 flag。

每个 scenario 保存原始 flag document，只修改一个 key，在 `finally` 中恢复原文。Oracle
为 `HEALTHY`、`FAULT_ACTIVE`、`UNKNOWN` 三态；`UNKNOWN` 不通过。32 个 seed 的数量、
难度和 fault 分配由 G02 Master Plan 冻结。

## Rejected alternatives

- Chaos Mesh/Toxiproxy：增加部署、权限和恢复面，但不增加 G02 必要证据。
- Online Boutique：第二个 SUT 不属于最小充分范围。
- 任意 shell/Kubernetes mutation：破坏 controller 的最小权限边界。

## Consequences

I-0017 负责 DSL schema、六个 adapter、oracle、32 seeds、clean-clone runner 和负例。
新增 fault family 或注入后端需要新 ADR 和候选。
