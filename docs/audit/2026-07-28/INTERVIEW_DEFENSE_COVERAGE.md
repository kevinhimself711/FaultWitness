# §19 交付物与 §20 追问清单的落点审查

## 为什么单独查这一节

`gates/G10.md:58` 把 I-G10-01 的通过标准写成"每套叙事能回答立项报告 §20 对应小节的追问
（§20.1-§20.11）"。这是一条**已经写进本审查的验收条件**，
所以 §20 里任何一个没有落点的问题，都是 G10 自己退出标准的缺口，不是外部建议。

§20 共 **11 小节 88 题**（报告 `:1370-1495`），前言写明
"以下问题不是背答案，而是项目必须产生真实证据"。
末行 `:1495` 本身是一条验收规则：
"任何简历指标在进入面试前都应能回答：定义、公式、样本、环境、版本、基线、结果、方差、失败分布。"

逐题反向检索后：**79 题有落点，9 题无落点，4 组半覆盖。**
四节完全覆盖（§20.3 多 Agent、§20.4 Tools/MCP/Skills、§20.7 评测与 Badcase、§20.9 安全）。

**本文件不照单全收这 9 条。** 判据仍是 README 的三条：能否撑起深度追问、
是否落在三个目标岗位族的核心素养、放在本项目里是否适配而不增加无谓复杂度。
按此筛选：**采纳 4 条，驳回 5 条。** 驳回理由与采纳理由同等重要——
它们本身就是"不过度设计"的记录。

## 采纳的四条

### 采纳 1：ADR 决策层缺失（Q16，同时影响 §19.1 十二条中的八条）

**这是九条里唯一的结构性缺口，也是最便宜的一条。**

报告 §19 第 3 项要求"至少 8 份关键 ADR"，§19.1 给出十二条最低清单（`:1355-1366`）。
仓库有 15 份 ADR（`docs/adr/INDEX.yaml`），数量达标，但**类型全部错位**：

| 现有 ADR | 类型 |
|---|---|
| ADR-0001 五平面、ADR-0002 outbox、ADR-0005 at-least-once、ADR-0006 唯一写入口 | 架构不变量 |
| ADR-0007 单节点 K3s、ADR-0008 Bailian 路由、ADR-0004 MinIO/DVC、ADR-0003 LangSmith | 基础设施选型 |
| ADR-0009、ADR-0014、ADR-0015 | 治理机制 |
| ADR-0010…ADR-0013 | G02 实验协议 |

§19.1 十二条里,**八条没有对应 ADR**：
为什么是 Agent 不是 Workflow、为什么先单 Agent、为什么选该 Orchestrator、
RAG/长上下文/SQL/知识图谱的选择、Dense/Sparse/Rerank、状态与 Checkpoint 存储、
Memory 写入与冲突、SSE 与断线恢复。

已覆盖的四条是：Tool/MCP 与权限模型（ADR-0006）、模型路由与 Fallback（ADR-0008）、
评测与 Judge（ADR-0012）、部署与扩展（ADR-0007）。

**为什么采纳**：成本极低而收益直接。这些决策**已经做过了**——
`LangGraph` 在仓库里出现 13 次（`FINAL_PLAN.md:35,57,79,142`、
`gates/G00/PLAN.md`、`gates/G01/PLAN.md:227` 的
"使用 `AsyncPostgresSaver` interface semantics，但禁止裸用默认 Saver"），
但**每一处都是技术栈罗列或实现约束，没有一处是选型论证**。
"为什么 LangGraph 不是 LangChain / Dify / 自研"是面经高频题，
而 §17.1 明确要求"最终选择必须有 ADR，不能因为'大家都用'而采用"。

这不是新增能力，是把既有判断补上记录。八份 ADR 各 1-2 页，合计 2-3 天。

**落点**：G03 增加一个 iteration 位（写 Agent/Workflow、单 vs 多 Agent、Orchestrator、
状态与 Checkpoint、SSE 五份），G04 阶段 A 与阶段 B 各写一份
（RAG 路线选择含 Dense/Sparse/Rerank；Memory 写入与冲突），
G10 I-01 的通过标准增加"§19.1 十二条各有一份 accepted ADR"。

**通过标准**：每份 ADR 必须含**被否决的备选方案**及否决理由。
只写"我们选了 X"的 ADR 不计入——它没有回答追问。

### 采纳 2：项目级 Problem Brief 缺失（Q7）

`REQ-BUS-001` 是 **P0 mandatory**，其 verification 原文：
"A versioned Problem Brief answers every field without invented customers or traffic."

仓库里 `problem_brief` 只作为**单个 fault case 的场景字段**存在
（`g02_baselines.py:238/256/269`），项目级 Problem Brief 文档不存在
（`docs/` 下无任何 brief/problem 命名文件）。`docs/gates/G02/REPORT.md` 的
Delivered scope 里也没有它。

**为什么采纳**：P0 mandatory 需求的 verification 没有产物，这是硬缺口。
而 Q7"为什么现成产品（Datadog Watchdog、PagerDuty AIOps、自建脚本）不能解决"
是 §20.1 的开题问——回答不了它，后面 87 题的价值都会被折价。
`竞品`/`开源方案` 在全仓库 0 命中，说明这个判断从未被写下来。

**落点**：G03 之前（属于 G02 的补偿性交付，但不重开 G02）或 G10 I-01 之内，
一份 ≤2 页的版本化 Problem Brief：真实用户、事故类别、基线工作流、
频率、失败成本、可伪证的成功判据，外加一节"为什么现成产品不够"。
**不虚构客户与流量**（§4.4）——用户就是 dogfooding 的自己与 ≤3 名私网使用者，如实写。

### 采纳 3：长上下文对照（Q50）

`长上下文` / `context window` 全仓库 0 命中。

**为什么采纳**：这不是补一个实验，而是补 Memory 这一整块的**立论前提**。
`REQ-MEM-004` 的 no-compression baseline（`gates/G04.md:197-202`）
是"压缩关掉但仍在同一窗口内"，它证明的是"压缩有没有损失"，
**答不了"为什么要做 Memory 和压缩，而不是把上下文窗口开大"**。
缺了这个 arm，G04 阶段 B 的 I-07…I-10、I-14 五个 iteration 全都少一个对照基线——
面试官只需一句"你为什么不直接用 128k 窗口"就能把整块工作问空。

成本是 I-G04-14 加一个 arm，不是新子系统。

**落点**：I-G04-14 的消融从两 arm（压缩 on/off）扩为三 arm：
压缩 on / 压缩 off / **长上下文（不做 Memory 检索，全量塞入窗口）**。
报告质量、成本、延迟三维。规模 S(2d) → S(2-3d)。

**预期结论方向**：长上下文 arm 很可能在质量上不差而在**成本**上显著更高——
这正是一个可讲述的数字，而不是"无显著差异"。若质量也不差且成本可接受，
那么诚实结论是"本项目规模下 Memory 的收益不成立"，
按 `FINAL_PLAN.md` "无收益机制不得进入默认架构"处理。**这个负结果同样是合格产物。**

### 采纳 4：Reward Hacking——采纳为"明确不做 + 理由"（Q80）

`reward hacking` 全仓库 0 命中。G09 I-04 只要求 10 个 GRPO update、规则化 Reward，
且冻结标准禁止任何质量提升主张（`gates/G09.md:97-104`）。

**为什么采纳，但不新增实验**：10 个 update 的规模根本探测不了 reward hacking，
硬做一个探测实验是过度设计。但**规则化 Reward 恰恰是最容易被 hack 的形态**——
本项目的规则 Reward 基于根因标签 + 证据 ID 匹配，
最直白的 hack 就是"多引用证据以提高命中率"或"输出所有候选标签"。
现在既没有实验，也没有把它列入"明确不做"，属于**判断缺失**而非能力缺失。

**落点**：`gates/G09.md` 的"明确不做"增加一条，说明
（1）规则 Reward 的两个可预见 hack 面；（2）为什么 10 个 update 的规模下不测；
（3）真正开始训练时的**第一道防线**是什么（Reward 与 eval 指标不得同源，
否则 hack 会同时提高两者而无法察觉）。
第三点与 I-G09-05 的"触发条件"天然衔接，加进那份归因报告即可，成本约 0.5 天。

## 驳回的五条

| 问题 | 驳回理由 |
|---|---|
| **Q38 embedding 选型实验** | `gates/G04.md:70` 已把 embedding 显式设为**控制变量**——这是正确的实验设计。再加 embedding 对照会稀释 chunk 与检索分段两个真正想测的因子。选型理由写进采纳 1 的 RAG ADR 即可，不需要实验 |
| **Q42 百万/千万级迁移** | 与已排除的 25/50 并发同构：单机 K3s 上的容量迁移数字不可信，报了是负资产。`REQ-RAG-007` 已降级为单点容量报告，理由一致 |
| **Q37 后半"为什么不是稀疏向量"** | 前半（sparse 段存在且可归因）已由 G04 I-03 覆盖。BM25 vs SPLADE 是检索方向的专精题，不落在本项目三个目标岗位族的核心素养上；`REQ-RAG-003` 只要求 "sparse retrieval"，未指定实现 |
| **Q63 并发上传与索引更新一致性** | G04 I-05 的增量/删除/冲突/回滚是串行集成测试，这是**恰当的范围**——本项目的知识库是运维文档与 Runbook，写入方是单一 dogfooding 用户，并发写入不是真实场景。为一个不存在的场景建并发一致性测试属于过度设计 |
| **Q66 的"灰度"半句** | 部署（G10 I-03）、监控（G01）、**动作回滚**（G05）、**索引回滚**（G04 I-05）都有落点。缺的只是 FaultWitness **自身**的发布灰度。这需要 Argo Rollouts/Flagger 一类渐进发布栈，是纯 CD 工程，与 Agent 能力无关，且单节点 K3s 上做灰度没有意义 |

**这五条应写入对应 Gate 的"明确不做"，而不是静默省略**——
与本审查对多模态、Batch、配额系统的处理方式一致。

## 半覆盖的四组：机制存在但无交付物收口

这几条不算无落点，因为机制确实找到了，缺的是把它变成可展示证据的 iteration。

**Q65 离线环境**：本地部署（ADR-0007）与模型网关（ADR-0008 +
`docs/runbooks/MODEL_GATEWAY.md`）覆盖充分。"离线"只以
`prepare_offline_base_images`（`infra.py:642`）形式存在——那是把 pinned image
送进私网节点的 bootstrap 手段，**不是产品的离线运行设计**。
建议：G10 I-03 的清洁环境部署演练里明确区分"离线安装"与"离线运行"，
后者如不做则记入"明确不做"。成本 0。

**Q81 旧模型下线**：升级侧机制真实——`REQ-EVAL-005` 的 locked 回归在
"Prompt, model, tool, retrieval, policy, or state behavior changes" 后触发，
G10 I-08 建门。下线侧只有 ADR-0008 的 "retain a NewAPI-compatible channel"，
无切换演练。建议：G08 I-04 的三模型族对照里附一次**模型族切换演练**
（把默认族换掉，跑一遍 locked 回归），成本约 0.5 天，
它同时给 Q81 与 ADR-0008 提供执行证据。

**Q52 为什么 Hit@K/Recall@K 选这个 K**：Recall@10 是冻结数值，
G07 I-03 要求指标注册表给出公式、聚合、门槛、CI、拥有产物五项，
但没有一项要求解释 **K 的取值理由**。建议：注册表增加一个 `rationale` 字段，
成本约 0.5 天。这条便宜且直接命中 `:1495` 的"定义、公式"要求。

**§20.11 Q85–Q88**：G10 I-06 只产出三个 git 数字，而**素材其实很充分**：

- Q86（止血与复盘）：`docs/engineering/badcases/BC-PROC-0001..0006` 六份可复现过程 badcase
  + GR-02–GR-12 防复发规则，其中 `BC-PROC-0004` 正是"错误处置掩盖了可定位失败"的完整复盘。
- Q87（防止 AI 弱化测试）：`AGENTS.md:27`（用户指令"never authorizes weaker safety,
  security, Eval N, thresholds, or failure semantics"）、`PHASES.md:24`、
  `validate_threshold_registry` 的 dict 相等检查（`g02_baselines.py:111`，
  由 `tests/g02/test_g02_baselines.py:140` 覆盖）、G07 I-03 的"未计算则报错"守卫。
- Q88（Harness 组成）：答案就是 `AGENTS.md` 本身——环境、`verify-fast` 工具、
  L1/L2/L3 判定层、安全不变量权限、direct debug loop 反馈闭环五项齐全。

建议：I-G10-06 从"三个 git 数字"扩为"三个数字 + 一节现有 harness 与防弱化机制的说明"，
成本约 1 天。**注意 `AGENTS.md:40` 明确禁止 "add a bespoke harness"**——
这一项是**把现有 harness 写清楚**，不是新建一个。这是 §20 最薄的一节，
而它的补齐成本几乎全是写作。
