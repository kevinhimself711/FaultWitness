# G06 设计：多租户 Runtime 与隔离

## 本 Gate 应当瘦身

G06 是 **T1 核心最少的产品 Gate**（仅 1 条），却在 `FINAL_PLAN.md:282-297` 被赋予了
最重的交付清单：Keycloak 四角色、PostgreSQL RLS、Qdrant ACL、MinIO 隔离、
quota / task queue / lease / heartbeat / deadline / backpressure、1-4 Worker、gVisor 或 Kata。

按 [REQUIREMENT_COVERAGE.md](../REQUIREMENT_COVERAGE.md) 的主题覆盖率：
`infra_runtime` JD 45% / 面经 **11%**，是全部主题里 JD 与面经都偏低的一档
（仅高于 data_pipeline、reliability、streaming）。而 `REQ-INFRA-001` 本身是 **P2、非 mandatory**。

**判断：保留 tenant 隔离与 lease/recovery，砍掉配额系统、调度器与沙箱管理层。**
理由不是这些技术不重要，而是：G01 已建成 OIDC + tenant 边界，G05 已建成最小权限与幂等，
G06 的边际收益主要落在"多 Worker 并发下这些机制是否仍成立"——这个问题用
1-4 Worker + lease + 崩溃恢复就能回答，不需要完整调度器。

**唯一例外是沙箱。** `FINAL_PLAN.md:290` 写"gVisor;不兼容时使用 Kata。二者均不可用则 Gate 失败"。
这条不能砍，因为它是 §0.1 之外的独立价值点：Agent 执行不可信代码的隔离是 Agent Infra 岗
JD 的明确要求，而且"我用 gVisor 跑沙箱，遇到 X 问题换 Kata"是具体的、可讲述的工程经历。
但**沙箱管理层**（镜像生命周期、池化、预热）可以不做。

## 冻结的退出标准（只能提高）

`FINAL_PLAN.md:292-297`：

1. 跨租户泄漏、任务丢失、重复动作副作用为 **0**。
2. Worker 在 lease 到期后 **30 秒**内恢复。
3. 1 到 4 Worker 的 Mock 吞吐提高至少 **2.5 倍**。
4. Sandbox escape、Secret 读取、未授权网络为 **0**。

第 3 条要注意口径：它写的是 **Mock 吞吐**，不是真实模型吞吐。这个措辞是对的——
真实模型调用受上游限流，4 Worker 不会线性提升。**保持 Mock 口径**，
并在报告里显式说明为什么用 Mock，否则这个 2.5× 会被质疑。

## 与 REQ-PERF-002 的冲突

`REQ-PERF-002` 要求在 **1 / 10 / 25 / 50** 并发下报告吞吐、P95、错误率、队列深度、资源。

按 [REQUIREMENT_COVERAGE.md](../REQUIREMENT_COVERAGE.md) 这一条被判为 **T3 可降级**：
单机 K3s 上 50 并发的数字不可信，报了反而是风险——面试官会问"你的硬件能撑 50 并发吗"，
而答案是不能，那这个数字就成了负资产。

**建议降到 1 / 10 两档**，并显式记录"25/50 未测量，原因是单机环境下结果不具代表性"。

但 `REQ-PERF-002` 是 **P0 mandatory**，且 `PHASES.md:24` 规定性能标准不得因实施简化而放宽。
因此这个降级**必须走修正案**（`docs/blueprint/AMENDMENTS/`），不能默默少测。
详见 [FINAL_PLAN_REVIEW.md](../FINAL_PLAN_REVIEW.md)。

## Iteration 划分

### I-G06-01：租户隔离（M，3-4d）

**交付**：PostgreSQL RLS、Qdrant ACL、MinIO 前缀隔离、Keycloak 四角色。

**T1 核心的唯一落点**（`REQ-INFRA-001` 降级后保留部分 + `REQ-RAG-006` 扩展）。

**Eval 与通过标准**：
- 跨租户泄漏 **0** — 冻结标准，零容忍
- 每个存储后端各有一个跨租户读取尝试并被拒
- RLS 在数据库层生效，不依赖应用层过滤 — 这是关键区分点

最后一条是面试可深挖点：应用层过滤一旦有一处遗漏就泄漏，RLS 是数据库强制的。
能讲清这个区别比"我做了多租户"有价值得多。

### I-G06-02：Lease、heartbeat 与崩溃恢复（M，3-4d）

**交付**：lease 获取/续期/过期，heartbeat，deadline。

**Eval 与通过标准**：
- lease 到期后 **30 秒**内恢复 — 冻结标准
- 任务丢失 **0**、重复动作副作用 **0** — 冻结标准，零容忍
- **接走 `REQ-AGT-003` 的第三段**：G03 建 checkpoint、G05 扩到外部副作用、
  G06 验证多 Worker 并发下仍成立

**这一项是 G06 的核心价值**。"Worker 挂了怎么办"是面经高频问题，
而 lease + checkpoint + 幂等三者配合的答案是完整的。

### I-G06-03：队列与背压（S，2-3d）

**T3 降级**（`REQ-REL-003`）：单 Worker 熔断 + 队列上限，**不建完整背压体系**。

理由：`REQ-REL-003` 是 P0，但 reliability 主题 JD 9% / 面经 16%，两侧都低。
熔断 + 队列上限足以回答"外部依赖挂了会不会把你打垮"。

**Eval 与通过标准**：
- 负载与故障测试约束队列增长、并发、恢复时间、被拒工作量
- 外部依赖失败不耗尽 Worker 池 — 零容忍

### I-G06-04：沙箱（M，3-4d）

**交付**：gVisor 运行时；不兼容则 Kata。

**Eval 与通过标准**：
- Sandbox escape、Secret 读取、未授权网络 **0** — 冻结标准，零容忍
- 三类逃逸尝试各有一个负例测试
- 记录 gVisor/Kata 的选型过程与遇到的兼容性问题（这本身是交付物）

**不做**：镜像生命周期管理、沙箱池化、预热优化。

### I-G06-05：性能基线（S，2d）

**交付**：1 / 10 并发下的吞吐、P95、错误率、队列深度、资源；1→4 Worker Mock 吞吐对照。

**Eval 与通过标准**：
- 1→4 Worker Mock 吞吐 ≥ **2.5×** — 冻结标准
- 报告固定硬件、数据集、provider 限制、预热条件（`REQ-PERF-002` 的 verification 要求）
- **显式记录 25/50 并发未测量及原因**

### I-G06-06：审计与权限扩展（S，2d）

**交付**：G05 的审计与最小权限在多租户下重新验证。

**Eval 与通过标准**：
- 审计链在跨租户视图下不泄漏其他租户信息 — 零容忍
- G05 的权限测试在 4 Worker 并发下重跑并通过

### I-G06-07：Secret 与 PII 全面 canary（S，2d）

**交付**：`REQ-SEC-003` 的第二段（跨 G01/G06/G10）。

G01 已建 `TraceSanitizer`，此处扩展到全部持久化与出口面（含新增的 Qdrant、MinIO、队列）。

**Eval 与通过标准**：
- Secret 与 PII canary 在每个出口面被拦截或脱敏 — 零容忍
- **不得为迁就指标命名而放宽 `_DENIED_KEY_PARTS`**（它含 `token` 且做子串匹配）

## 与其他 Gate 的联动

| 联动 | 方向 | 关键点 |
|---|---|---|
| `REQ-AGT-003` G03→G05→G06 | 三段式 | 本 Gate 是最后一段，验证并发下的 checkpoint 幂等 |
| `REQ-TOOL-003` G05→G06 | G05 起 | 最小权限扩展为 RLS + 四角色 |
| `REQ-REL-002` G05→G06 | G05 起 | 幂等在并发 Worker 下重新验证 |
| `REQ-SEC-004` G05→G06 | G05 起 | 审计扩展到跨租户视图 |
| `REQ-RAG-006` G04→G06 | G04 起 | ACL 过滤扩展为 Qdrant ACL |
| `REQ-SEC-003` G01→G06→G10 | 三段式 | 本 Gate 是第二段 |
| `REQ-PERF-002` G06→G08 | G06 起 | 性能基线供 G08 优化对照使用 |

**G05→G06 有四条联动**，是全项目最强耦合。G06 不应被大幅推迟，否则 G05 的四个机制
在并发下暴露问题时返工面很大。

## 规模

七个 iteration，约 **17-21 天**。

原设计（含完整配额系统、调度器、沙箱管理层、四档并发）估计需 28-35 天。
瘦身后节省的时间应转移到 G03 与 G04 阶段 A——那里的 T1 密度高得多。

## 明确不做

- **配额系统**。quota 的价值在于多租户计费与公平性，本项目没有真实租户。
- **调度器**。1-4 Worker 用简单队列 + lease 即可，不需要优先级、亲和性、抢占。
- **沙箱管理层**。镜像生命周期、池化、预热都不做。
- **25/50 并发测量**。降为 1/10 两档，需修正案记录。
- **`REQ-INFRA-001` 的完整形态**。P2 非 mandatory，降为最小骨架。
  若最终主投 Agent Infra 岗，可在 G10 之后作为独立扩展回补。
