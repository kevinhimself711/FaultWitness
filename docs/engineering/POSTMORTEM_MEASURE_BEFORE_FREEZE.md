# 先量后冻：本项目最贵的一课

来源：操作者本地 `CLAUDE.md`「先量后冻」一节，记录于 2026-08-11。
内容与宿主、网络、凭据无关，是关于测量设计与治理失效的推理，故入库保存。以下逐字复制。

**症状**：做完实验才发现 baseline 早就很好了。这不是一次意外，是同一个错误的第三次复发。

**代价（可数）**：3 个 metric 版本、7 份修正案、AMD-0007 里 8 个事后补丁段、
8 个 `-invalidated-*` 运行目录、r1–r9 里 3 轮作废。全部花在同一件事上——
修一个**在没有任何有效测量之前就被冻结的比较基准**。

**成因**：`+5pp` 当初钉在 G02 实测的 `deterministic 0.500` 与 live `0.000` 上。
后来发现 `0.500` 是规则表缺陷、`0.000` 是标签格式 artifact。也就是说门槛被钉在了
**两个仪器故障读数**上。治理层的"已冻结，只能提高"于是把一个经验性猜测
（当前难度就是下界）变成了不可下调的规则：仪器错了也只能走修正案，
而修正案越贵，就越有动力把结果解读成通过。r8 的假通过正是这条链的终点——
`ready` 由一条冻结在测量之前的统计条件产出，而制造那个"显著"的恰是它本应检出的缺陷。
现在 `max(0.70, best+0.10)` 要求 `core_e2e >= 1.0167`，单位区间上无解，是同一病的末期。

**教训，按可操作性排序**：

- **区分两类"冻结"。** 程序、安全边界、失败语义、`diagnostic_only` 这类**定义**，
  实现前冻结是对的，继续这样做。而**引用某个实测量的数值目标**
  （"比最佳基线高 5pp"里的那个"最佳基线"）在拿到一次可信测量之前**不要冻结**，
  写成"待定，由第一次通过有效性检查的运行确定"。冻结定义，不要冻结未知数。
- **先花最便宜的钱证伪仪器，再花模型预算。** 本项目最有效的一次诊断是单特征多数投票
  分类器——零模型成本就证伪了"baseline 太强"。它本该在第一轮之前跑，而不是第五轮之后。
  上线前的顺序：泄漏探针 → 分化度 → 披露对称性 → 才买 trial。
- **披露对称性是硬检查项。** 任何评分标准必须对**所有被比较的臂**同等披露；
  若对照臂按构造直接获得答案而被测臂必须自己推断，这个比较就是无效的，
  且它的失效方式是**让门通过**，不是让门失败。r8 就是这样过的。
- **冻结的目标变成数学上不可能，是设计缺陷的信号，不是待满足的指标。**
  出现这种情况就停下来报告，别去凑。同样别为了让标签好看去动谓词
  （r9 的 `blocked_reason` 落在 `unclassified` 而不是 `dataset_too_easy`，
  这是判据链的标签盲区，记录即可，不改）。
- **预登记你的预期，然后如实记录它被否证。** r9 之前我预登记了三条 arm 的重算值与
  `dataset_too_easy`；实测三条都低于重算值、落在 `unclassified`。
  重算不等于实测——把这句话写进预登记里，事后就不能重新解释。
