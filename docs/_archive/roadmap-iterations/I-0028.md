# I-0028 — Byte-Exact Remote Process Transport Corrective

## 状态

Completed on implementation candidate `09693ceb52a883113c82ac1a7be489e826bad04f`。
正常预计 **1h00**，仅为可观测计划值，不是 kill timeout。

## 目标

纠正 EVAL-G02-012 暴露的 Windows 文本模式换行改写。所有 SSH stdin 均以显式 UTF-8
bytes 进入 binary subprocess，stdout/stderr 再显式解码；脚本、sudo credential 与命令行
继续保持三个隔离 channel。

## 可证伪假设

真实 Windows child process 收到的脚本 byte sequence 与调用方 UTF-8 bytes 完全一致，LF
不变为 CRLF；oversized script 仍不进入 argument list，执行和清理失败仍 fail closed。

## 冻结验证边界

- transport case 仅 4 个：real-process byte equality、bounded/separate channels、cleanup on
  execute failure、cleanup/path fail-closed；不得扩成远程或统计矩阵。
- V-G02-009/V-G02-011 Iteration N 保持 4；V-G02-010 Iteration N 保持 0。
- remote、Gate L2、破坏性 scenario、external service 与 model call 均为 0。
- 完成时 `open_evidence: []`；I-0026 与 I-0027 永不重开。

## 实现

`_remote_process` 只接受调用方 text 并在唯一 subprocess 边界显式 UTF-8 encode；child
process 以 `text=False` 接收 bytes，capture 后再显式 UTF-8 decode。真实 child-process
regression 比较完整 stdin hex；mock runner 仅保留 channel、cleanup 与错误注入职责。

## 结果

EVAL-G02-013 的 4/4 cases 全部通过。真实 Windows CPython child process 收到的 stdin hex
与调用方 UTF-8 bytes 完全相同且无 `0d0a`；oversized script、sudo credential 和 argument
channel 保持隔离，execute/cleanup/path 错误均 fail closed。

V-G02-009/V-G02-010/V-G02-011 Iteration N 保持 4/0/4；remote、Gate L2、破坏性、external
service 和 model execution 均为 0，`open_evidence: []`。证据 commit
`c8757c026b84c49b56291f7a49083a3087b3e370` 是候选的 asset-only 后代。
