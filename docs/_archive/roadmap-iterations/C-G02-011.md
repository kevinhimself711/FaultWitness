# C-G02-011 — Deterministic Payment Workload Corrective

## Status

Completed on candidate `bd374683de25b824af8669a993c8c7b771c6001e` with no open evidence.
This forward corrective does not reopen A-G02-010 or any other terminal work item.

## Root cause

C-G02-010 correctly replaced unsafe ten-user ambient load with one user, but the payment fault
branches still depended on incidental checkout timing. A-G02-010 therefore observed no checkout or
payment connection-error trace during SEED-G02-0002 even though injection, collection, cleanup, and
the frozen 90-second window all behaved correctly. Kafka already avoided the same defect by sending
one explicit candidate-bound checkout after injection.

## Scope

Reuse that existing checkout path for `paymentFailure` and `paymentUnreachable`. Send exactly one
request after injection, allow its expected non-2xx checkout response to be observed, and let the
unchanged correlated trace oracle decide whether the fault is active. A missing transport result
remains `infra_failed`; an uncorrelated trace, cleanup failure, or oracle miss remains blocking.

## Non-goals

- Changing N, the two fault observations, 30-second spacing, 90-second window, recovery, or cleanup.
- Raising ambient load or resources, or changing any runtime image.
- Running any Gate L2 matrix, baseline, model call, or downstream aggregate.

The corrective closes only after targeted tests and one candidate-bound `paymentUnreachable` real
scenario pass through the existing runner.

## Result

All 38 G02 lab tests passed. The candidate then recreated `fw-sut` 24/24 Ready and executed one
`paymentUnreachable` scenario in 95.6 seconds. The stimulus sent exactly one cart and checkout;
cart returned 200 and the expected faulted checkout returned 500. Both frozen fault observations
contained one correlated checkout error and one payment connection error. Exact restoration matched
the original digest and both recovery observations were healthy, producing
`HEALTHY → FAULT_ACTIVE → HEALTHY`. Gate L2 execution and model calls were zero.
