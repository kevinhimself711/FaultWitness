# C-G02-012 — Replay-Stable Trace Envelope Corrective

## Status

Completed on candidate `86a459c0bec1bcf3e583fd1280fbca2667479d2e` with no open evidence.
This forward corrective does not reopen A-G02-011 or any other terminal work item.

## Root cause

The six-stage probe derived its trace reference from candidate and environment, but generated every
timestamp from the remote wall clock. A-G02-011's first invocation persisted the reference before an
outer command failure; replay reused that reference with different timestamps, so the trace buffer
correctly raised `PayloadConflict`.

## Scope

Use the immutable candidate commit timestamp, normalized to the strict UTC `+00:00` contract form,
for `emitted_at`, `started_at`, and `ended_at` in trace and canary envelopes. Keep the existing trace
ID derivation and six-stage content. A replay of the
same candidate/environment operation must therefore be byte-equivalent and receive normal duplicate
handling. Provisioning and access requests remain outside this timestamp path.

## Non-goals

- Changing stage count, names, correlation, Tempo/LangSmith targets, or any metric and threshold.
- Deleting the conflicting negative trace or retrying A-G02-011.
- Running any Gate phase or model call inside the corrective.

The corrective closes only after the existing collector tests and the same real candidate-bound
trace operation succeed twice without a payload conflict.

## Result

The first implementation candidate exposed one missing UTC-normalization boundary and was rejected
by the strict downstream contract before persistence. The final candidate passed the strict contract,
deployed 1/1 Ready, provisioned the existing probe binding, and returned the same six-stage result
from two exact trace invocations without a payload conflict. Gate L2 and model execution remained
zero; `open_evidence` is empty.
