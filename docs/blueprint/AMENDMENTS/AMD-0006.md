# AMD-0006 — Establish metric v2 before G03

Status: accepted

Date: 2026-07-28

## Reason

The closed G02 evidence is honest but its scorer cannot serve as the G03 comparison boundary:

- the deterministic rule matched field presence, so the ambient `working_set` field intercepted
  three unrelated fault classes;
- live prompts did not disclose the closed camelCase label set used by exact-match scoring;
- evidence truth contained every observation ID, so any non-empty citation subset scored 1.0;
- critical-claim support was self-reported by the evaluated model;
- no-tool trials reported tool-schema validity as 1.0 instead of `N/A`;
- dead-loop and family floors had no runner evidence; and
- resource cases omitted metric ownership and units, while the CPU and memory oracles accepted
  startup/scrape artifacts as faults.

Changing only the deterministic signature would make the frozen 32-case matrix score 1.0 by
reading evaluator-derived booleans. That would turn G03's frozen `best baseline + 5pp` exit into an
impossible 1.05 target. Metric v2 therefore removes the shortcut before remeasurement.

## Amendment

Metric v1 remains the immutable interpretation of all G02 reports and artifacts. Metric v2 is the
only comparison definition permitted for G03 and later work:

1. `metric_version` is `2`.
2. The closed root-cause labels are `productCatalogFailure`, `adHighCpu`, `emailMemoryLeak`,
   `paymentFailure`, `paymentUnreachable`, and `kafkaQueueProblems`; every live prompt discloses
   this full set and the scorer rejects noncanonical labels.
3. The public packet projects every case into the same six atomic evidence groups. It excludes
   evaluator-derived oracle booleans and fault stimuli. Metric ownership and units are explicit.
4. Sealed truth declares disjoint `required_evidence` and `distractor_evidence`. Evidence precision
   is supported citations divided by all citations. Complete required evidence is a separate Core
   E2E obligation.
5. A diagnosis contains exactly one typed `root_cause` claim with evidence references. The scorer,
   not the evaluated model, determines whether that critical claim is supported.
6. The JSON Schema in the runner is executable. Malformed output, noncanonical labels, unknown
   evidence, and distractor citations have distinct failure classes.
7. `tool_schema_validity` and `dead_no_progress_loop` are explicitly `not_applicable` before G03
   and name their G03 runner and artifact proof obligations. `fault_family_success` is calculated
   from Core E2E by DSL family. A registered floor that is neither calculated nor explicitly
   inapplicable fails closed.
8. The seven frozen floor operators and values are byte-for-byte unchanged. The Core E2E
   expression is resolved by a closed implementation, never by general expression evaluation.
9. Resource cases are replayed with the existing scenario runner. Email memory establishes a
   nonzero same-pod baseline before injection and requires material post-baseline growth. Ad CPU
   establishes a stimulated healthy baseline and requires both an absolute and relative increase.
   The remaining 24 independent scenario observations are retained.
10. The three baselines are rerun at N=32 deterministic and N=192 live. Results are non-Gate G03
    readiness evidence; they do not edit, relabel, or supersede the G02 Gate report.

The G03 `best baseline + 5pp` comparison remains unchanged. If the metric-v2 result would require a
value above 1.0, G03 stays `not_started`; no cap, baseline exclusion, or threshold reduction is
authorized by this amendment.

## Publication boundary

The repository audit is restored inside `verify-fast`. It checks lockfiles, pinned GitHub Actions,
licenses, source ownership, publication secrets/local paths, and the CycloneDX SBOM. This is a
local safety check, not a lifecycle, changed-path, HEAD-binding, or remote-merge gate.

## Unchanged contracts

This amendment does not change G02's historical scores, Gate status, sample counts, confidence
method, model route, fallback prohibition, token limits, cost accounting, Ground Truth isolation,
locked-test isolation, sanitizer, permissions, or failure semantics. It does not authorize G03
implementation or the five G03 I-01 cross-Gate contract additions.
