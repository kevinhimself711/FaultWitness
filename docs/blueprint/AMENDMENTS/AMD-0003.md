# AMD-0003 — Allow Unlimited Attributable Infrastructure Retries

Status: accepted

Date: 2026-07-23

Owner: project owner

## Context

The frozen G02 plan stopped an environment compatibility obstacle after three attempts or 45
cumulative minutes. During the I-0017 lab rollout this converted recoverable source-transfer,
preflight-regex, namespace, and registry failures into a mandatory stop before the required live
evidence existed. The project owner explicitly removed that attempt/time ceiling and directed the
rollout to continue until it passes.

## Amendment

- Infrastructure, rollout, credential-transfer, and external-tool attempts may be repeated without
  an attempt-count or cumulative-time ceiling.
- Every attempt remains candidate-, config-, artifact-, and environment-bound and records its
  attributable result. A retry does not erase or relabel a prior failure.
- A known deterministic root cause must be corrected before another attempt; an unchanged retry is
  allowed only for an attributable transient infrastructure failure.
- Metric failures, cleanup failures, policy denials, digest drift, and zero-tolerance failures remain
  blocking. Unlimited retries are not an operator pass path and do not lower any Gate quality floor.
- Trial-internal sample counts, model token ceilings, and the one transient retry inside a paid model
  attempt remain unchanged. This amendment changes infrastructure execution attempts, not the
  preregistered statistical experiment.

## Impact

G02 no longer blocks solely because the same compatibility obstacle reached three attempts or 45
minutes. Budget estimates remain planning estimates rather than stop conditions; actual elapsed
time and failed attempts are reported. The preimplemented fallback preference remains, but it is no
longer mandatory after a fixed number of attempts.
